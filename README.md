## 1. מבוא והגדרת המערכת
מערכת זו נועדה לנהל ולייעל את הפעילות השוטפת של בית המרקחת בבית חולים, תוך שמירה על בטיחות המטופלים ובקרה הדוקה על מלאי התרופות.

* **הנתונים הנשמרים במערכת:** 
  המידע המנוהל כולל את פרטי המחלקות השונות בבית החולים (קומה, סוג, קיבולת ומנהל), המטופלים המאושפזים, הרופאים המטפלים והתמחויותיהם, מלאי מחסן התרופות (כולל מעקב אחרי מספרי אצווה ותאריכי תפוגה), מרשמים רפואיים, ותיעוד פעולות הניפוק של הרוקחים. כמו כן, המערכת מנהלת קטגוריות מתקדמות של תרופות באמצעות ירושה (תרופות רגילות, תרופות הדורשות קירור, ותרופות מפוקחות/כספת).
* **הפונקציונאליות העיקרית:**
  ניהול מלאי מדויק, התראות על ספי סף, הפקת מרשמים על ידי רופאים מורשים, מעקב אחר ניפוק תרופות בפועל למחלקות ולמטופלים, וקשור ישיר בין פריטי המלאי לניפוקים.

## 4. החלטות עיצוב ונימוקים
במהלך תכנון מסד הנתונים ונירמולו לרמה השלישית (3NF), נתקבלו מספר החלטות אדריכליות מרכזיות:
1. **מימוש ירושה בתרופות (`MEDICATION` ותתי-הטבלאות):**
   * *החלטה:* קיימת טבלת אב ראשית (`MEDICATION`) המרכזת את הנתונים הכלליים של כל תרופה, לצד טבלאות מומחות (`REGULARMED`, `FRIDGEMED`, `SPECIALMED`).
   * *נימוק:* מאפשר הפרדה נקייה של מאפיינים ייחודיים (כגון טווח טמפרטורות למקרר או קוד כספת לתרופות מפוקחות) מבלי להעמיס שדות ריקים (`NULL`) מיותרים בטבלה הראשית.
2. **אילוצי תוקף ובדיקות (`CHECK` & `DEFAULT`):**
   * בטבלת המטופלים (`PATIENT`) הוגדר ערך ברירת מחדל למגדר (`Female`) יחד עם אילוץ תקינות.
   * בטבלת המחלקות (`WARD`) הוגבל מספר הקומה לטווח שבין 7- ל-10, והקיבולת חויבה להיות גדולה מ-0 לשמירה על הגיוון העסקי של המערכת.
3. **ניהול קשר רב-רבים בניפוק (`DRAWN_FROM`):**
   * *החלטה:* הפרדת פעולת הניפוק מהמלאי באמצעות טבלת קשר ייעודית.
   * *נימוק:* מאפשר מעקב מדויק במקרים שבהם ניפוק מרשם נלקח ממספר פריטי מלאי או אצוות שונות במחסן.

## 5. מילון נתונים (Data Dictionary)

### טבלת מחלקות (WARD)
| שם השדה | סוג נתון | מפתח | תיאור השדה |
| :--- | :--- | :--- | :--- |
| `WardID` | INT | PK | מזהה חד-חד ערכי של המחלקה |
| `Floor` | INT | - | מספר הקומה בה נמצאת המחלקה (בין 7- ל-10) |
| `WardType` | VARCHAR(50) | - | סוג המחלקה (למשל: כירורגיה, פנימית) |
| `Capacity` | INT | - | קיבולת המטופלים המקסימלית (גדול מ-0) |
| `HeadNumID` | CHAR(9) | - | תעודת הזהות של מנהל המחלקה |
| `Phone` | VARCHAR(15) | - | מספר טלפון ליצירת קשר עם המחלקה |

### טבלת מטופלים (PATIENT)
| שם השדה | סוג נתון | מפתח | תיאור השדה |
| :--- | :--- | :--- | :--- |
| `ID` | CHAR(9) | PK | תעודת זהות של המטופל |

| `LastName` | VARCHAR(50) | - | שם משפחה של המטופל |
| `DateOfBirth` | DATE | - | תאריך לידה של המטופל |
| `Gender` | VARCHAR(10) | - | מגדר (Male / Female, ברירת מחדל: Female) |
| `Phone` | VARCHAR(15) | - | מספר טלפון אישי |

| :--- | :--- | :--- | :--- |
| `MedicationCode` | INT | PK | קוד תרופה ייחודי |

### טבלת ניפוק תרופות (DISPENSING)
| שם השדה | סוג נתון | מפתח | תיאור השדה |
| :--- | :--- | :--- | :--- |
| `DispenseID` | INT | PK | מזהה פעולת ניפוק |
| `PharmacistName` | VARCHAR(50) | - | שם הרוקח המנפק |
| `DispenseDate` | DATE | - | תאריך הניפוק |
| `QuantityDispensed` | INT | - | כמות שנופקה (חייב להיות גדול מ-0) |
| `DispenseStatus` | VARCHAR(20) | - | סטטוס הניפוק (למשל: בוצע, ממתין) |

### טבלאות ירושה של תרופות (REGULARMED, FRIDGEMED, SPECIALMED)
- **`REGULARMED`**: מכילה תרופות רגילות (`MedicationCode` משמש כ-PK וכ-FK לטבלת `MEDICATION`).
- **`FRIDGEMED`**: מכילה תרופות הדורשות קירור, כולל טווח טמפרטורות (`TempRange`) ומזהה מקרר (`FridgeID`).
- **`SPECIALMED`**: מכילה תרופות מיוחדות/מפוקחות, כולל קוד כספת (`SafeCode`).

| `QuantityRequested` | INT | - | כמות מבוקשת במרשם (גדול מ-0) |
| `UrgencyStatus` | VARCHAR(20) | - | רמת דחיפות |
| `Status` | VARCHAR(20) | - | סטטוס המרשם |
